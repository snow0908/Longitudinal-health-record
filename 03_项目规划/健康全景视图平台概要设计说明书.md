## 1. 引言

### 1.1 目的

本文档旨在以**领域驱动设计（DDD）** 方法论为核心，明确阐述健康全景视图平台的业务边界、领域模型与架构设计。文档为项目的各方利益相关者提供清晰的技术蓝图，确保对设计方向和原则的共识，并为后续详细设计与开发阶段奠定坚实基础。

### 1.2 适用范围

适用于项目管理、开发、测试、运维等多个阶段。本文档作为团队沟通的**统一语言（Ubiquitous Language）** 载体，确保所有角色对系统业务语义有一致理解。

### 1.3 术语与缩略语

| 术语 | 说明 |
|:---|:---|
| **全景视图** | 患者360°全周期健康数据的统一展示页面 |
| **限界上下文** | DDD中的业务边界，在边界内模型具有一致语义 |
| **聚合根** | DDD中的聚合入口，负责维护聚合内部的数据一致性 |
| **领域事件** | 领域中发生的重要业务事件，用于解耦 |
| **CQRS** | 命令查询职责分离，读写模型分离的架构模式 |
| **防腐层（ACL）** | 隔离外部系统模型变化对内部领域影响的适配层 |
| **脱敏** | 对患者敏感信息进行部分隐藏或替换处理 |
| **闭环** | 医嘱从开立、审核、执行到结果反馈的完整流程追溯 |

## 2. 项目背景

在"健康中国2030"战略引领下，全民健康管理对数据整合与可视化提出了更高要求。然而，当前居民健康信息分散存储于不同机构和平台，缺乏有效的整合与共享机制。本项目旨在构建一个**以患者为中心的、覆盖全生命周期的健康全景视图平台**，通过领域驱动设计实现业务复杂度的有效管理。

**核心业务目标**：

1. 为医护人员提供患者360°全周期健康数据的一站式展示
2. 为管理人员提供灵活的全景视图配置能力（模块、模板、脱敏、权限）
3. 为居民提供个人健康数据的查阅与隐私控制
4. 为审计人员提供完整的调阅行为追溯能力

## 3. 领域战略设计

### 3.1 限界上下文划分

依据业务语义的强内聚性，将系统划分为 **4个限界上下文（Bounded Context）** ，每个上下文拥有独立的领域模型与通用语言。

```
┌─────────────────────────────────────────────────────────────────────┐
│                        健康全景视图平台                              │
├───────────────┬───────────────┬───────────────┬───────────────────┤
│  患者全景视图  │   配置管理     │   审计日志     │    居民端         │
│  上下文        │   上下文       │   上下文       │    上下文          │
│ (核心域)       │ (支撑域)       │ (通用域)      │   (核心域)         │
├───────────────┼───────────────┼───────────────┼───────────────────┤
│ • 患者索引     │ • 模板管理     │ • 访问日志     │ • 实名认证         │
│ • 就诊时间线    │ • 模块配置     │ • 调阅日志     │ • 隐私设置         │
│ • 全生命周期    │ • 场景配置     │ • 统计图表     │ • 调阅安全锁       │
│ • 收藏管理      │ • 脱敏配置     │               │ • 个人数据查阅      │
│ • 个人设置      │ • 水印管理     │               │                    │
│                │ • 通用设置     │               │                    │
└───────────────┴───────────────┴───────────────┴───────────────────┘
```

### 3.2 各限界上下文详述

#### 3.2.1 患者全景视图上下文（核心域）

- **业务使命**：以患者为中心，整合展示全生命周期健康数据
- **核心能力**：
  - 患者主索引查询与跳转
  - 就诊时间线展示（含时序图）
  - 全生命周期阶段划分与数据聚合
  - 医护收藏管理
- **通用语言示例**：患者360、就诊时序图、概况视图、生命阶段、就诊事件

#### 3.2.2 配置管理上下文（支撑域）

- **业务使命**：为全景视图提供灵活的配置与管控能力
- **核心能力**：
  - 模板可视化配置（字段拖拽、接口绑定）
  - 模块生命周期管理（新增/编辑/启用/停用）
  - 角色场景权限配置
  - 数据脱敏规则配置
- **通用语言示例**：模板、模块、场景、脱敏规则组、水印

#### 3.2.3 审计日志上下文（通用域）

- **业务使命**：记录所有访问与调阅行为，保障数据安全可追溯
- **核心能力**：
  - 系统登录访问日志
  - 三方系统调阅日志（电子病历/健康档案/基本信息）
  - 调阅行为图表分析
- **通用语言示例**：调阅日志、访问溯源、三方系统

#### 3.2.4 居民端上下文（核心域）

- **业务使命**：赋能居民自主管理个人健康数据与隐私
- **核心能力**：
  - 居民注册与实名认证
  - 个人健康数据查阅
  - 隐私保险箱（时间/业务维度隐私设置）
  - 调阅安全锁与访问即时通
- **通用语言示例**：实名认证、隐私保险箱、调阅安全锁、访问即时通

### 3.3 上下文映射关系

| 源上下文 | 目标上下文 | 映射模式 | 说明 |
|:---|:---|:---|:---|
| 患者全景视图 | 外部数据中心 | **防腐层（ACL）** | 隔离外部CDR数据模型变化，转换为内部领域模型 |
| 配置管理 | 患者全景视图 | **发布语言（PL）** | 通过配置中心发布模块、模板配置，全景视图订阅应用 |
| 审计日志 | 患者全景视图 | **事件驱动** | 全景视图产生调阅事件，审计日志异步接收 |
| 居民端 | 患者全景视图 | **共享内核** | 共用患者核心模型，但各自维护扩展属性 |

### 3.4 通用语言词汇表

| 业务术语 | 代码命名 | 上下文 |

| 生命阶段 | `LifeStage` | 全景视图 |

## 4. 系统架构设计

### 4.1 总体分层架构

系统采用 **CQRS + 四层DDD架构**，实现读写分离与关注点隔离：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                            接口层（Interface Layer）                         │
│                    REST API / Web MVC / 三方调阅接口                         │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
┌─────────────────────────────────────────────────────────────────────────────┐
│                          应用层（Application Layer）                         │
│           工作流编排 / 事务管理 / 权限校验 / 事件发布                         │
│  ┌─────────────────────────┐  ┌─────────────────────────────────────────┐   │
│  │   Query Service         │  │   Command Service                       │   │
│  │   （读模型，直查数据）    │  │   （写模型，调用聚合根）                 │   │
│  └─────────────────────────┘  └─────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
┌─────────────────────────────────────────────────────────────────────────────┐
│                           领域层（Domain Layer）                             │
│                聚合根 / 实体 / 值对象 / 领域服务 / 领域事件                    │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐ ┌─────────────────────┐   │
│  │  Patient    │ │ Encounter   │ │  Template   │ │DesensitizationRule  │   │
│  │  聚合根      │ │  聚合根      │ │  聚合根      │ │   聚合根             │   │
│  └─────────────┘ └─────────────┘ └─────────────┘ └─────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────────┘
                                      │
┌─────────────────────────────────────────────────────────────────────────────┐
│                        基础设施层（Infrastructure Layer）                     │
│        Repository实现 / 外部API调用（ACL） / 消息队列 / 缓存                 │
│  ┌─────────────────────────────────────────────────────────────────────────┐ │
│  │                    防腐层（Anticorruption Layer）                        │ │
│  │         将外部CDR数据模型转换为内部领域模型                               │ │
│  └─────────────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 5. 领域战术设计

### 5.1 核心聚合设计

| 聚合根 | 所在上下文 | 核心业务逻辑（不变性约束） | 关联子实体/值对象 |
|:---|:---|:---|:---|
| **Patient** | 患者全景视图 | 必须通过 `PatientId`（主索引）唯一标识；过敏标签变更需记录领域事件 | `Encounter`（就诊列表）、`AllergyStatus`（VO）、`Favorite`（收藏） |
| **Encounter** | 患者全景视图 | 就诊号唯一；就诊时间不可晚于当前时间；诊断列表按时间排序 | `Diagnosis`（VO）、`VitalSign`（VO）、`MedicationOrder`（实体） |
| **Template** | 配置管理 | 模板名称唯一；停用时需校验是否被场景引用；字段映射需符合API响应结构 | `TemplateField`（VO）、`ApiBinding`（VO） |
| **Module** | 配置管理 | 模块编码全局唯一；层级关系（分类→模块→子模块）通过父子关联维护 | `ModuleConfig`（VO）、`SubModule`（实体） |
| **Scene** | 配置管理 | 场景编码唯一；密钥自动生成不可重复；角色权限映射无冲突 | `RolePermission`（VO）、`SceneKey`（VO） |
| **DesensitizationRuleGroup** | 配置管理 | 同一角色下不能配置冲突的脱敏规则；规则变更触发缓存清理事件 | `Rule`（实体）、`FieldMapping`（VO） |
| **PrivacyVault** | 居民端 | 隐私设置按时间+业务维度唯一；黑名单机构调阅触发验证流程 | `PrivacyItem`（VO）、`BlacklistOrg`（VO） |
| **AccessLog** | 审计日志 | 日志一旦写入不可修改；调阅类型与内容必须匹配 | `AccessDetail`（VO） |

### 5.2 核心值对象

| 值对象 | 所属聚合 | 属性 | 说明 |
|:---|:---|:---|:---|
| `LifeStage` | Patient | `stageType`, `ageRange`, `startDate` | 生命周期阶段，基于患者年龄计算，无唯一标识 |
| `VitalSign` | Encounter | `temperature`, `pulse`, `respiration`, `bloodPressure`, `recordTime` | 生命体征，不可变，替换即新建 |
| `Diagnosis` | Encounter | `icdCode`, `diagnosisName`, `diagnosisType`, `doctor`, `diagnosisTime` | 诊断信息，遵循ICD10标准 |
| `TemplateField` | Template | `fieldName`, `dataType`, `sourcePath`, `displayFormat` | 模板字段映射，指向数据源路径 |
| `SceneKey` | Scene | `keyValue`, `createdAt`, `expireAt` | 场景密钥，用于三方系统调阅鉴权 |
| `PrivacyItem` | PrivacyVault | `businessType`, `startDate`, `endDate`, `isProtected` | 隐私设置项，按业务+时间维度定义 |

### 5.3 领域服务

| 领域服务 | 所在上下文 | 职责 |
|:---|:---|:---|
| `TimelineBuilderService` | 患者全景视图 | 根据就诊数据构建时间线视图，计算各阶段数据密度 |
| `LifeStageCalculatorService` | 患者全景视图 | 基于患者出生日期计算当前所属生命周期阶段 |
| `TemplateRenderService` | 配置管理 | 根据模板配置将原始数据渲染为HTML/PDF/CDA文档 |
| `PermissionCheckService` | 配置管理 | 结合场景配置与通用设置，判断当前用户对特定数据是否有访问权限 |
| `DataAggregationService` | 患者全景视图 | 跨子域（临床+公卫）聚合数据，用于全生命周期视图展示 |
| `DesensitizationEngine` | 配置管理 | 根据脱敏规则对敏感字段进行脱敏处理（掩码/替换/隐藏） |

### 5.4 仓储接口

| 仓储 | 所属聚合 | 核心方法 |
|:---|:---|:---|
| `PatientRepository` | Patient | `findById(patientId)`、`findByCondition(name, idNumber)` |
| `EncounterRepository` | Encounter | `findByPatientId(patientId)`、`findByEncounterId(encounterId)` |
| `TemplateRepository` | Template | `findByType(templateType)`、`findByScene(sceneId)` |
| `ModuleRepository` | Module | `findByContext(contextType)`、`findByParent(moduleId)` |
| `SceneRepository` | Scene | `findByRole(roleId)`、`findByKey(sceneKey)` |
| `DesensitizationRuleRepository` | DesensitizationRuleGroup | `findByRole(roleId)`、`findByGroup(groupId)` |
| `AccessLogRepository` | AccessLog | `save(log)`、`queryByCondition(time, org, type)` |

## 6. 模块设计

基于DDD分层架构，各模块设计如下：

### 6.1 患者全景视图上下文

| 模块 | 层级 | 功能描述 |
|:---|:---|:---|
| **患者索引查询** | 接口层+应用层 | 支持按姓名、身份证号等多条件筛选患者列表，跳转至360视图 |
| **就诊时间线** | 应用层+领域层 | 以时间线/列表视图展示患者就诊记录，支持就诊类型与日期筛选 |
| **就诊时序图** | 应用层+领域层 | 住院患者诊疗数据按时间轴展示（体温单、医嘱、检查检验等） |
| **全生命周期** | 应用层+领域层 | 按生命阶段聚合医疗服务与公共卫生数据 |
| **收藏管理** | 应用层 | 医护收藏患者，支持快速跳转 |
| **个人设置** | 应用层 | 用户自定义全景视图模块显隐与顺序 |

### 6.2 配置管理上下文

| 模块 | 层级 | 功能描述 |
|:---|:---|:---|
| **模板管理** | 领域层 | 模板CRUD、字段拖拽配置、接口调试、效果测试、导入导出 |
| **模块配置** | 领域层 | 全景视图业务模块的生命周期管理（内置/三方/自定义） |
| **场景配置** | 领域层 | 按角色配置模块访问权限，自定义场景与密钥管理 |
| **脱敏配置** | 领域层 | 脱敏规则组管理、角色分配、效果预览 |

## 9. 领域事件清单

### 9.1 事件定义

| 事件名称 | 触发条件 | 携带数据 | 处理方式 |
|:---|:---|:---|:---|
| `PatientViewedEvent` | 用户进入患者360页面 | `patientId`, `userId`, `viewType`, `timestamp` | 异步→审计日志记录 |
| `PatientViewedEvent` | 同上 | 同上 | 异步→消息推送（若配置启用） |
| `EncounterAccessedEvent` | 用户查看某次就诊详情 | `encounterId`, `userId`, `accessSource` | 异步→审计日志记录 |
| `TemplateChangedEvent` | 模板新增/修改/删除 | `templateId`, `changeType`, `operator` | 异步→清除Redis缓存 |
| `ModuleStatusChangedEvent` | 模块启用/停用 | `moduleId`, `newStatus`, `operator` | 异步→刷新场景权限缓存 |
| `DesensitizationRuleChangedEvent` | 脱敏规则变更 | `ruleGroupId`, `changeType`, `operator` | 异步→清除脱敏缓存 |
| `PrivacySettingChangedEvent` | 居民隐私设置变更 | `patientId`, `privacyItems` | 异步→刷新隐私保险箱缓存 |
| `AbnormalAccessDetectedEvent` | 调阅密码连续错误3次 | `patientId`, `orgId`, `attemptCount` | 异步→发送告警短信 |

### 9.2 事件处理流程（以 `PatientViewedEvent` 为例）

```
┌─────────────┐    ┌─────────────┐    ┌─────────────────────┐
│  用户打开   │───▶│ 应用层接收  │───▶│  发布领域事件        │
│  患者360    │    │  请求       │    │  PatientViewedEvent  │
└─────────────┘    └─────────────┘    └──────────┬──────────┘
                                                  │
                          ┌───────────────────────┼───────────────────────┐
                          │                       │                       │
                          ▼                       ▼                       ▼
              ┌─────────────────────┐ ┌─────────────────────┐ ┌─────────────────────┐
              │  审计日志订阅者      │ │  消息推送订阅者      │ │  统计订阅者          │
              │  记录访问日志        │ │  发送短信/邮件通知   │ │  更新调阅统计        │
              └─────────────────────┘ └─────────────────────┘ └─────────────────────┘
```

## 10. 非功能性需求

### 10.1 约束与限制

- 基础业务库支持SQL Server
- 系统兼容Chrome、Safari、Edge、360浏览器（极速模式）
- 自适应分辨率≥1440×900，低于此分辨率出现滚动条

### 10.2 性能需求

| 场景 | 响应时间要求 |
|:---|:---|
| 一般时段页面响应 | ≤1秒 |
| 高峰时段统计页面 | ≤3秒 |
| 登录响应 | ≤1秒 |
| 患者搜索（非高峰） | ≤1秒 |
| 全景视图首次加载 | ≤3秒（含外部数据拉取） |

### 10.3 安全性需求

- **权限控制**：基于角色的细粒度数据访问控制（RBAC）
- **数据脱敏**：敏感字段按配置规则自动脱敏
- **调阅审计**：所有数据访问行为可追溯
- **水印防护**：全局水印防止截图泄密
- **传输加密**：全链路HTTPS加密传输

### 10.4 维护性需求

- 日志级别支持动态调整（ERROR/DEBUG）
- 配置变更支持热加载，无需重启服务
- 支持模板、场景等配置的导入/导出，便于环境迁移
